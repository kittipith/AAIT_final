Cache HIT

มี entry ที่ตรงกันและยังใช้ได้อยู่ (matching valid entry exists)

  • นำผลที่เก็บไว้มาใช้ซ้ำ
  • Function body ไม่ถูกรัน
  • Fast path: คืนค่าจาก cache ทันที
Cache MISS

ไม่มี entry ที่ตรงกันหรือยังใช้ได้

  • Execute the function (รัน body จริง)
  • Store its returned result เก็บผลไว้
  • Slow path: สร้าง entry ใหม่

แนวคิด hit/miss นี้เป็น framework-independent model ใช้ได้กับ cache ทุกระบบ ไม่ได้มีแค่ใน Streamlit

6 Cache Identity: ต้อง “งานเดียวกัน” ถึงจะ HIT W10★★

Streamlit ต้องตัดสินว่า call นี้คืองานที่เคยทำไปแล้วหรือเปล่า โดยดู 3 อย่าง (เป็นแนวคิดของ cache key)

A · Cached functionเป็นฟังก์ชันที่ decorate ตัวเดียวกัน
B · Relevant argumentsค่า argument ตรงกับ call ก่อนหน้า (ยกเว้น argument ที่ตั้งใจตัดออก เช่นที่ขึ้นต้นด้วย _)

💡 Key point

9 st.cache_resource: ใช้ object ตัวเดียวร่วมกัน W10★

MISSสร้างหรือโหลด resource แล้วเก็บ object นั้นไว้ใน cache

10 Copy vs Shared object: ตัวอย่าง Append 99 W10★★★

cache_data: callers receive copies

User A กด Append → เห็น [1, 2, 3, 99] ส่วน User B ยังเห็น [1, 2, 3] เพราะสำเนาแยกข้อมูลออกจากกัน (copies isolate data)

User A กด Append → object กลายเป็น [1, 2, 3, 99] User B จะเห็น object ที่ถูกแก้แล้วใน rerun ครั้งถัดไป

11 Hashing inputs: parameter ต้อง hashable และการยกเว้นด้วย _ W10★★

A · Why hash?Streamlit ต้องมี key ที่เสถียร ไว้เทียบ call นี้กับ call ก่อนหน้า จึงแปลง (hash) argument เป็นค่าที่เปรียบเทียบได้
B · Underscore escape hatchใส่ _ นำหน้า parameter เมื่ออยากให้ Streamlit ไม่สนใจ parameter นั้น (เช่น object ที่ hash ไม่ได้ อย่าง connection)
⚠ Key point
อย่า ignore parameter ที่การเปลี่ยนค่าของมันควรทำให้ผลลัพธ์เปลี่ยน ไม่อย่างนั้นจะได้ผลเก่าที่ผิด (stale/wrong hit)
🛠 เชื่อมกับ Lab 10
ใน Lab 10 แปลง list ของข้อความเป็น tuple(tickets_df["text"]) ก่อนส่งเข้า train_classifier_cached(texts, labels) เพราะ tuple เป็นข้อมูล immutable ที่ hash ได้ จึงใช้เป็นส่วนหนึ่งของ cache key ได้อย่างเสถียร

16 Wrap-up: Rerun → Look up → Reuse หรือ Recompute W10

  1. การโต้ตอบใน Streamlit ยังทำให้ script rerun ส่วน cache hit แค่ข้าม body ของ cached function
